课程设计

这门课最难的地方，不是知识点，是顺序

具身智能的教学有一个陷阱：任何一个环节单独讲都成立，但学员在真实硬件上第一次动手时， 会因为一个串口权限、一个舵机 ID 冲突、一个零位偏移而卡住两天，然后失去信心。

所以我把 15 天设计成三条同时推进的线：先把硬件点亮，再把数学补上，最后让模型接进来。 每一天都以"能看见的产出"结束——不是"讲完了"，而是"它动了"。

线 1 · Day 1–4

让硬件活过来

组装、通电、通信协议、参数配置、零位标定。这一段不追求优雅，只追求"12 个舵机能按我说的角度转"。

线 2 · Day 5–8

让它知道自己在哪

URDF 建模、正解、逆解、主从遥操作、多臂联机。从"给角度"升级到"给位姿"。

线 3 · Day 9–15

让它看见并听懂

OpenCV、YOLO、手眼标定、图像伺服、Function Calling、MCP 服务。最后交付一个能对话的机械臂。

设计上的核心取舍：逆解用解析法而非数值迭代，视觉先用 HSV 再上 YOLO，智能体先做 Function Calling 再做 MCP。 每一步都让学员能自己推导、自己调试，而不是调用一个黑盒。零基础的人只有"看得懂每一层"，才不会在第三层崩掉。

15 天结构

每一天都有可验收的产出

DAY1
行业认知与环境搭建
具身智能的三层结构（感知 / 认知 / 行动）、行业能力矩阵、15 天路线图。
编程热身不用 Hello World，用一个多文件结构的坦克大战小游戏，让零基础学员第一天就习惯"项目 = 多个模块"。
产出：Linux 环境就绪，能读懂并运行一个多文件 Python 项目
DAY2
机械臂安装
按"结构件 / 执行件 / 传动与固定 / 线束 / 感知 / 工具"六类清点与装配。这一天的隐藏难点是线束： 走线位置决定了后面每一次转动会不会扯断连接。
产出：6 自由度整机装配完成，通电自检通过
DAY3
Feetech SCS 舵机通信协议与参数配置工具
从指令帧结构讲到内存表：READ 0x02 / WRITE 0x03 / SYNC_WRITE 0x83， 校验和怎么算、广播为什么危险。
然后要求学员自己写一个配置工具——批量改 ID、读写 PID 参数、单步试转。
产出：能手工构造合法指令帧；自研舵机参数配置工具可批量下发
DAY4
初始状态标定工具开发
问题的来源讲清楚：同一批机械臂、同一个姿态，读出来的 counts 都不一样；不做标定，后面所有运动学都在错误基线上运行。
带学员做一个标定 GUI，把每个关节的零位偏移记录成 CSV，可保存、可回放、可复用到其他机器。
产出：一套可复用的零位标定流程 + 标定记录文件
DAY5
URDF 建模、运动学正解与逆解
平台是 SO-ARM100 兼容结构，URDF 与 3D 网格直接取自开源件——不让学员重画模型，而是要求他们读懂这份模型： 关节树怎么串、link 与 joint 的坐标系如何嵌套、mesh 原点和视觉原点为什么不是一回事。
读完就自己实现：齐次变换矩阵逐关节推导末端位姿，逆解走解析法解耦——θ₁ 由底座回转直接求出， θ₂–θ₄ 退化成平面三连杆，θ₅–θ₆ 单独解腕部姿态。全程不调用现成运动学库，1,148 行代码自己写。 课上专门讲多解：同一个目标位姿有 8 组解，哪一组能用取决于关节限位和干涉。
产出：给定关节角能算末端位姿；给定位姿能求出可用关节角
DAY6
angle_relay 中继服务与 Leader-Bridge
为什么必须有中继：一体式方案（leader_bridge.py）把读和写写死在一个进程里， 一旦要加视觉或加第二条臂就得改内核。
改成解耦的四端口中继 + 生产-消费模型后，任何一端都能独立替换。Leader-Bridge 用 WebSocket 做通道，按 7 步递进实现。
产出：主从遥操作跑通，人拖动一台，另一台同步跟随
DAY7–8
物理臂 Producer / Consumer 双模式与多臂联机
同一台物理臂既可以是生产者（读 counts → 转弧度 → 广播），也可以是消费者（收弧度 → 转 counts → 写舵机）。
加上录制回放，就得到一条完整链路：拖一次 → 存下来 → 多台臂同时复现。这是后面做双臂协同的全部基础。
产出：一条臂示教，多条臂复现；多对多联机控制可用
DAY9
OpenCV 图像识别与目标像素定位
HSV 色彩空间、背景差分、颜色与纹理检测。重点不在 API，在三个反复出现的易错点： 色彩空间用错、阈值在换光照后失效、waitKey 既管刷新又管退出导致画面卡死。
产出：能稳定输出目标物体的像素坐标，画面不卡
DAY10
YOLO 目标检测训练与部署
采集不用手工标 500 张：背景减除 + GrabCut 自动抠图，6 类 × 5 张 = 30 张就能起训， 程序自动生成标注。YOLOv8n · 50 epoch · 约 100 秒。
配套 diag_yolo.py 做训练诊断——学员第一次训模型，八成问题出在数据而不是网络。
产出：属于自己的物体检测模型，能实时推理
DAY11
眼在手标定与图像伺服
先讲摄像头该装哪、不能装哪，以及姿态控制三原则。
标定方法刻意避开复杂的张正友：人眼把末端对准 TCP，摄像头只负责记录偏差。物理偏移量直接测量。 这是零基础学员能独立完成、且精度足够抓取的方案。
产出：像素坐标 → 物理坐标的映射关系建立
DAY12
视觉抓取闭环 + 大模型结构化指令
上午做闭环：minAreaRect 取旋转角 → 末端旋转对齐 → IBVS 逼近循环 → 虚拟夹持判定。 课上明确列出必须定义的 6 项参数，缺一项就调不出来。
下午讲大模型的三种输出模式：自由文本 → 结构化 JSON → Function Calling。这是"能聊天"和"能干活"的分界线。
产出：视觉抓取闭环可用；一句话能被解析成结构化动作指令
DAY13
通用 MCP 智能体设计方法
从"手动档"到"自动档"：讲清 name / description / parameters 三要素， 以及为什么工具描述写得含糊，模型就一定会用错——这是智能体设计里最被低估的一课。
产出：能为一个能力设计出模型可正确调用的工具描述
DAY14
机械臂 MCP 服务设计与实现
把机械臂注册成 MCP 工具：串口路径、舵机映射、通信链路分级测试（先 ping 通、再单舵机、再整机、最后接模型）。
重点讲两大核心风险与对应的保护措施——模型会给出越界角度，没有限位保护就会撞机。
产出：机械臂作为 MCP 服务被大模型直接调用，一句话驱动多步动作
DAY15
项目验收答辩
考核两项硬指标：多对多联机控制、多机械臂之间传递物品。 要交的不只是代码，还要讲清自己在哪一步卡住、怎么定位、最后怎么解决的。
产出：完整项目演示 + 答辩通过，具备独立开发能力

这门课证明了什么

能把一件事做到，和能让一百个人做到，是两种能力

一个人自己跑通一条技术链路，说明他有执行力。把这条链路拆成 15 天、让 100 个零基础的人 每天都有产出、并且在每个人卡住的地方提前准备好工具——这要求对链路上每一个失败点都有第一手的记忆。

小班教学可以靠现场答疑兜住问题，100 人不行。规模一旦上来，任何一处含糊都会变成几十个人同时卡住， 所以课程必须自己消化掉全部歧义：指标怎么测、报错怎么读、参数为什么是这个值。 是这个规模把课程逼成了体系，而不是反过来。

课程里所有自研工具，都是先有人卡在那里，才有这件工具。所以这份材料的真正内容不是 26,000 行代码， 而是那 6 个卡点的清单——它是这条技术路线上会失败的地方的完整地图。
